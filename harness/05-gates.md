# 05. 게이트 (R5)

## G1. 가이드 위반 게이트 (S5, 기계)
입력: runs/<run>/s3-s4/s4-nodes.json (S4가 figma MCP로 추출한 노드 속성)
기준: design.md YAML (SSOT)

| 항목 | 허용 값 | 통과 조건 |
|---|---|---|
| 프레임 크기 | 390×844 | 최상위 프레임 전부 일치 |
| 색상 | design.md `colors` 20개 hex | 목록 밖 색상 0개 |
| 모서리 | 2 / 6 / 8 / 24 / 32 / 50 / 9999 | 목록 밖 값 0개 |
| 간격 (gap, padding) | 1 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 96 | 목록 밖 값 0개 |
| 글자 크기 | 12 / 16 / 18 / 20 / 24 / 26 | 목록 밖 값 0개 |

- 글자 크기 목록은 design.md YAML에 `mobile.fontSizes`로 추가
- 실패 시 → S4 복귀 (최대 3회)

## G2. 원칙 게이트 (S2 + S5, 기계) ★ story-service.md "어기면 안 되는 것"
입력: runs/<run>/s2/s2-spec.md, runs/<run>/s3-s4/s4-nodes.json의 텍스트 레이어

| 원칙 | 적용 화면 | 통과 조건 |
|---|---|---|
| ① AI는 이유를 보여주고, 결정은 사람이 해요 | store-review, game-setup | 금지어 `자동 불합격` `자동 탈락` `자동 게시` `자동 발행` 0건 / store-review: `합격` `보류` `불합격` 3개 모두 + `이유` 1개 이상 |
| ② 날짜를 바꾸면 관련된 일이 빠짐없이 보여야 해요 | calendar, event-detail | `설치 시간` `일할 사람` `가게 안내` `돈 계산 마감일` `장소 겹침` 5/5 + `적용` 1개 이상 |

- 실패 시 → S2 복귀 (최대 3회)

## G3. 사람 승인 게이트 (S1 끝, 1곳)
- 승인자: 팀장님
- 통과 조건: state.json `approvals`에 `{"stage":"S1","by":"팀장님","result":"approved"}` 1건
- 반려 시 → S1 분석 다시 (최대 3회)

## S3 시안 선택 (게이트 아님, 입력)
- 내부 관계자 협의 결과를 state.json에 기록
- 통과 조건: `{"stage":"S3","pick":N}`에서 N은 1~3
- 전부 반려 시 → S3 다시 (최대 3회)

## 판정 스크립트 공통
- 통과: exit 0
- 실패: exit 1 + 위반 목록 출력 (`파일 / 항목 / 실제 값 / 허용 값`)

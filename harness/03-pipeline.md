# 03. 파이프라인 (R3)

## 단계
| 단계 | 묶는 작업 (story-work #) | 입력 | 출력 |
|---|---|---|---|
| S1 리서치 | 1 수집 + 2 분석 | screen, keywords, prd.md | 레퍼런스 목록 + 반영할 부분 목록 |
| S2 설계 | 3 화면 설계 문서 | S1 출력, story-service.md | 화면 설계 문서 |
| S3 키스크린 | 4 키스크린 + 5 협의 대기 | S2 출력, design.md | figma 키스크린 2~3개 → 확정 시안 번호 |
| S4 디자인 | 6 토큰·컴포넌트·화면 | 확정 시안, design.md | 토큰·컴포넌트·화면 figma 프레임 |
| S5 검토 | 7 가이드 위반 검토 | S4 figma, design.md, story-service.md | 검토 결과 |

## 단계 간 전달 형식
- 단계마다 .md 파일 1개
- 고정 제목: `## 입력`, `## 출력`, `## figma URL` (figma를 쓰는 단계만)
- 다음 단계는 직전 단계의 .md 파일만 읽음
- figma 결과물은 URL로만 기록

## 되돌아가는 지점
| 실패 상황 | 되돌아갈 곳 | 최대 횟수 |
|---|---|---|
| 팀장님 컨펌 반려 (S1 끝) | S1 분석 다시 (수집 결과 재사용) | 3회 |
| 협의에서 시안 전부 반려 (S3 끝) | S3 키스크린 다시 | 3회 |
| 원칙 게이트 G2 실패 (S2·S5) | S2 설계 수정 | 3회 |
| 가이드 위반 1건 이상 (S5) | S4 디자인 수정 | 3회 |

3회를 넘으면 자동 재시도를 멈추고 나(디자이너)에게 넘김.
